## 1. The idea

CrystalBallStock is a product for people who don't have the time to watch different stocks throughout the day. It's an app for people who just want to be able to take a glance at some basic numbers that show what the trend of the stock is compared to other companies in the same markets and the news. Even with this simplification of the data, there are options for people who like to watch the stock, with links that lead directly to the sources of data such as a CSV export and the articles that the data is based on.
  The problem with other apps is that they don't create a simplified overview of the data. These apps are difficult to navigate, where you have to go through many menus to get to the stocks, and once you get to them, there is so much information that it can just overwhelm the average user. Whereas in Wealthsimple, the watchlist usually only pins the stock and gives the current price, my app gives you the % change over the previous trading period.
  The design of the app doesn't offer as many customization options as the other apps, such as connecting to external banking apps and stock traders. If I could get the ads working, I would make them the main revenue source of the app, where the user would just see them on the sides of the screen no intrusive ads or redirects that make it hard to click the features of the app, just passive ads. This ad direction wouldn't generate as much revenue as intrusive ads, but it might build a user base that wants to come back because the ads wouldn't interrupt the app experience while still offering some of the better API options.

## 2. Where IT creates value

 For my webpage, the first aspect of the value chain would be operations, where the raw data from Yahoo, with both the financials and the news, will be processed into graphs using the news, current, and past trade values, which uses data to create an estimate of upcoming trade sessions. This is an example of using data to simplify complex information. Without this compiled data, the user would have to go to different sites and find a way to combine and relate the stocks. The next link would be outbound logistics, which would be the site itself. Then the user would be able to see the data from operations as graphs for the user, and the other information gathered, like the news pages related to the stocks and current prices, is accessible to the user via quick links and an exportable CSV, creating a quick way to gather a lot of information.

## 3. Network effects

This site doesn't have a network effect. For example, if a user who isn't you signs up and uses their own watchlist on the site, existing users wouldn't see any change in any of the site's features, such as the graph or any other tools the site offers. But if that user posts an external site or just mentions it by word of mouth, about using the tool to get some stock data, this wouldn't add value directly to an existing user but would add possible growth value to the site in the form of possible new users that the post would bring in.
  In the current state of the website, existing users don't benefit from new users joining, thus not having any network effects. When you first create an account, you can access all of the features of the app, such as all of the graphs and projections, so other people joining the site won't affect the experience. The popular stocks page, shows what stocks are either in an up or down state based on the information that was pulled from the external Yahoo Finance API, since this data is external it wouldn't create any network effect on the site. 
  This site would be 1-sided. With the one side being the user, where they could view graphs and connected information and export CSV files. If the user wants to create an account, they would gain access to a watchlist and a history of previously viewed stocks.
  With all of this, it isn't built yet, but in the future it would be beneficial to add something like a chat section where people could ask others questions about stocks and others could give answers to their questions, but it could lead to moderation problems such as scams or spam. This could help add a network effect and make it so new users would be able to get help from others who have experience in the app or other trading platforms.

## 4. Can it be copied? (the moat question)

With the site being made using GitHub Copilot AI, this makes it quite easy to replicate the basic site. The look of the site is a quite basic layout where many other AI tools and models create sites that look very similar. The graphs are also basic plots of Yahoo Finance data, so these styles and features are easy to imitate.
  One of the things that I implemented into the site that might be harder to copy would be the algorithm for estimating the price of a certain stock for later trading sessions. A company would be able to get close to this algorithm using the data provided by the Yahoo Finance API, but if they just ask the AI model to estimate the future price, it would probably just use a predictive model based on the previous data of that certain stock, which is what happened to me when I first tried to create the predictions. My algorithm uses many different sources of data, like the current price and previous prices. But after looking at the data, the original AI model didn't take into account some of the extrinsic factors that affect stocks, such as other companies in the sector from the Yahoo Finance API or internal factors within the company itself, where I get this information from the Yahoo News API.
    Valuable: With this algorithm, it just uses the data that is provided by the free API. This approach is more comprehensive than the basic one originally given by the AI, but it could be better. With more time and resources, I would want to create an AI model that refines itself with the predicted price based on the actual price when the trading session ends. Compared to the previous predictions made by each of the other models, this would refine the data points to try to more accurately estimate the price. 
  Rare: There are a couple of other sites that use this type of model, but just doing a basic overview of them and looking at some pages like Reddit, some of these users state that they function well with backdated data but struggle to keep up with the unpredictable shocks of real-life trading, so it isn't rare. Whereas the model I would want to make would take into account news stories like the one I have deployed but add other factors that have been announced in the news or directly from the company, using a larger API that is able to gather more information from different countries and languages to guide the model.
  Hard to Imitate: This type of site would be fairly easy to replicate but would require some thinking. A larger company, where they have the time and resources to make their own model and train it, would make it easier to copy the model and improve on it. But it would take some time to refine it, and after the model is created, it would take time to train it to possibly get a more accurate prediction of the price. But even with just the prebuilt ones, companies or individuals may face usage or storage constraints.
  Non-substitutable: The same type of user that uses this app wants to gain information about the stock market. They could just look at Yahoo Finance or brokers for stock information or AI tools like ChatGPT or Claude to gather this information. But the raw stock data can be hard to read with a lot of financial data. Learning to interpret it and make predictions might take a lot of time. With AI models, they don't always have updated information, and some can make up information, known as hallucinations in the data. This means it can be substituted, but it might have some potential drawbacks compared to this site. In the methodology tab, it explains an overview of how the model predicts and gives the percentage error for the estimated price. Other models do this. Of the sites it checked, many of them didn't disclose how they calculate or display the error percentage. This might be easy to imitate, but many of these sites wouldn't want to disclose this, keeping a tighter competitive advantage.
  Over time, this model that I'm using to estimate the price of the stock will gather more information about the stock but might eventually become obsolete, and newer models that are better at predicting will come out.

## 5. Cloud and operations

To make this app run in a real deployment, I would want to have email verification mentioned. This would require SaaS that would cost you a yearly fee to keep the domain so it can send out the emails. With the current setup, I'm hosting it on Cloudflare on a free account. With this SaaS, the interaction that the page is allowed to have is limited. So it would be costly and time-intensive to scale. If either the clould flair or Yahoo goes down, this will create catastrophic failure in the site.

## 6. Risks and ethics

On the website as it currently is, there isn't much protection other than the basic one provided by Cloudflare and the hash method created by Copilot. This means that without proper encryption, passwords and other sensitive data that the user provided to the site could be at risk. With a proper deployment, you would want to have hashing or use another encription method on this data when it is being sent, so it is decrypted only when the user can see it. If this data gets breached, this could cause a huge problem for the user. Such as someone reusing passwords or a scammer getting access to your phone number and address. Another thing that could go wrong for the user would be that the prediction would be quite off from the real number, meaning that the user would put their money into a stock that would loose them money. What I did in this deployment is to state that the model could be wron and to only use it as a reference, but to still verify the data.
